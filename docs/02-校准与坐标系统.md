# 02 校准与坐标系统

## 坐标系

- 控制台 `/click?x=&y=` 与固件内部 `cx/cy` 都是**整屏分数**（含 Safari 工具栏，左上角 (0,0)）。
- 标定页回传 `/calrep` 是**视口分数**（不含工具栏）。换算：
  `fy = (顶部内边距 + ry×vh) / 横屏高`、`fx = rx`（横屏时视口宽=屏宽）。
  本机实测 vh=730 / 横屏高 768 → 顶部内边距 38pt。
- 换算过的整屏分数可直接喂给 `syncbase`，**无需隐藏工具栏**。

## 校准原理（产率法，推荐）

iPadOS 指针对 HID count 的响应是**线性**的（与移动距离无关，已用 3× 距离复测验证），
产率 = 每个数产生的整屏分数位移。流程：

1. 标定页打开 + 广播开着。随便点一发 `/click`（点在页面中部安全区 30%~70%）。
2. 读 `/status` 的 `rx/ry`（视口分数）→ 换算成整屏分数。
3. 产率 = |实际Δ分数| ÷ |命令 counts|。
   命令 counts = (目标分数 × cx − 起点 counts)，起点看 `/status` 的 `px/py`。
4. 新参数：`cx = 1/产率x`、`cy = 1/产率y` → `/config?cx=&cy=`
5. **必须重建基准**：`/mouse?op=syncbase&x=&y=`（用回传换算后的当前指针整屏分数）。
   改 cx/cy 会让旧基准换算失效，不重建基准 = 全部点击偏移。
6. 双点验证：syncbase 后打两个靶（如 (0.5,0.5)、(0.3,0.7)），读 `/calrep` 误差 <±0.5% 即完成。

实测参考（iPadOS 17.7 默认指针速度）：X≈0.00367、Y≈0.00481 整屏分数/count
→ `cx≈273、cy≈208`。

## 大坑清单

1. **辅助触控悬浮球 ≠ 指针**：悬浮球（灰圆 ~30px，常停屏幕边缘）与静止指针渲染几乎一样；
   真指针在深色背景上是**大半透明圆 + 中心白点**。微移一发即可区分（球不动指针动）。
   锚定一律用 `/calrep` 回传，眼睛只做交叉验证。
2. **「指针速度」滑块**：iPadOS 设置 → 辅助触控 → 指针设备 → 指针速度。
   滑块一动产率就变（实测曾翻倍），必须重校。
3. **cy 有下限 80 钳制**（`/config` 回包里能看到钳后值）。
4. **手势区**：顶部=下拉通知中心、底部=回主屏。固件的相对位移跟踪从不把指针顶向边缘，
   但手动 `op=zero` 会压到左上角——日常用 syncbase 就好，不要频繁 zero。

## syncbase 是什么

iPad 蓝牙鼠标在 BLE 重连/重启后系统会把指针挪到别处，而固件的逻辑坐标基准还在旧位置
→ 点击整体偏移。`syncbase` 用"指针现在真实在哪"重写基准，不移动指针。
触发时机：ESP32 重启后、iPad 重启后、你手动挪过指针后、校准改完 cx/cy 后。
